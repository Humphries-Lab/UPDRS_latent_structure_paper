# `data/`

This folder contains the raw Parkinson’s Progression Markers Initiative (**PPMI**) input files used by the GEMINI analysis pipelines.

These files are read by the scripts in:

* `Dimensionality_Reduction/`
* `DBS_prediction_model/`

Nothing in this folder is generated by the code. All files are downloaded from the PPMI portal or provided as PPMI analytic data files.

---

# Important access note

> **This repository is private and restricted to approved lab members.**
>
> The PPMI files in this folder are committed so that approved lab members can clone the repository and reproduce the analysis without re-downloading the data.
>
> Everyone with access to this repository must have their own approved PPMI account and must comply with the PPMI Data Use Agreement.
>
> Do **not** add collaborators to this repository unless they are approved to access PPMI data.

Before making this repository public, see [Before making this repository public](#before-making-this-repository-public).

# Obtaining the data

Lab members cloning this private repository should already have the required data because the files are committed with the repository.

To refresh or re-download the data:

1. Register and request access through the PPMI portal:
   https://www.ppmi-info.org/access-data-specimens/download-data

2. Download the required study-data tables.

3. Place the files in the exact folder structure shown above.

4. Keep the exact filenames, because the scripts refer to them directly.

# Main data folders

## `MOTOR_2024/`

This is the main input folder for the current dimensionality reduction and DBS prediction pipelines.

It is read by:

* `data_set_up.data_pre_process_all_visits_version_2025()`
* `DBS_prediction_model/1_check_dbs_status_in_data.py`

| File                                                         | PPMI table | Contents                                                              |
| ------------------------------------------------------------ | ---------- | --------------------------------------------------------------------- |
| `A_MDS-UPDRS_Part_I.csv`                                     | `NUPDRS1`  | UPDRS Part I — non-motor experiences of daily living, clinician-rated |
| `B_MDS-UPDRS_Part_I_Patient_Questionnaire.csv`               | `NUPDRS1P` | UPDRS Part I — non-motor experiences of daily living, self-reported   |
| `C_MDS_UPDRS_Part_II__Patient_Questionnaire.csv`             | `NUPDRS2P` | UPDRS Part II — motor experiences of daily living, self-reported      |
| `D_MDS-UPDRS_Part_III.csv`                                   | `NUPDRS3`  | UPDRS Part III — clinician-administered motor examination             |
| `E_Modified_Schwab___England_Activities_of_Daily_Living.csv` | `MODSEADL` | Modified Schwab & England Activities of Daily Living                  |

### Key columns used

| Column                 | Meaning                        |
| ---------------------- | ------------------------------ |
| `PATNO`                | Patient identifier             |
| `EVENT_ID`             | Visit identifier               |
| `INFODT`               | Visit date                     |
| `PDSTATE`              | Medication state, ON or OFF    |
| `DBSYN`                | DBS status                     |
| `PDTRTMNT` / `PDMEDYN` | Treatment or medication status |

The Part III table carries the `PDSTATE` and `DBSYN` fields used for ON/OFF medication-state selection and DBS-status checks.

### Note on `MODSEADL`

The `MODSEADL` item is not used as a model feature and is dropped downstream. However, the file is required for the pre/post-DBS analysis and must be present.

### Note on folder naming

The current pipeline uses:

```text
MOTOR_2024/
```

Some older, unused functions in `data_set_up.py` may still refer to:

```text
Motor___MDS-UPDRS/
```

Only `MOTOR_2024/` is required for the current pipeline.

## `demographics/`

This folder contains participant demographic and medication-related files.

These files support non-symptom covariates such as:

* age
* sex
* levodopa equivalent daily dose, or LEDD
* participant status
* cohort information

Expected files include:

| File                                  | Provides                                            |
| ------------------------------------- | --------------------------------------------------- |
| `LEDD_Concomitant_Medication_Log.csv` | Levodopa equivalent daily dose per patient or visit |
| `Demographics.csv`                    | Date of birth and sex, used to derive age at visit  |
| `Participant_Status.csv`              | Enrolment status and cohort assignment              |

These covariates are planned for use in the DBS prediction model alongside the low-dimensional UPDRS symptom-space coordinates.

> **Status:** These demographic covariates are currently staged for future model additions. Update this section once the loading code is fully integrated into `DBS_prediction_model/`.

# Top-level data files

## `Code_List_-__Annotated_.csv`

This file contains the annotated PPMI code list.

It is used by `data_formatting_functions.py` to map item codes to readable symptom descriptions.

For example, it supports:

* feature-code lookup
* symptom labels in loading plots
* UPDRS section groupings

This file must remain at the top level of `data/`.

## `PPMI_Consensus_Committee_Analytic_Datasets_23Oct2023.xlsx`

This file contains the PPMI Consensus Committee analytic dataset used for cohort selection.

It is read by:

```python
data_formatting_functions.select_patient_list()
```

The relevant sheet is:

```text
PD
```

The cohort classification uses the following columns:

| Column     | Meaning                                      |
| ---------- | -------------------------------------------- |
| `CONPD`    | Consensus Parkinson’s disease classification |
| `CONLRRK2` | LRRK2 mutation-carrier flag                  |
| `CONGBA`   | GBA mutation-carrier flag                    |
| `CONSNCA`  | SNCA mutation-carrier flag                   |
| `CONPRKN`  | PRKN mutation-carrier flag                   |
| `CONPINK1` | PINK1 mutation-carrier flag                  |

The pipeline defines cohorts as:

| Cohort     | Definition                                             |
| ---------- | ------------------------------------------------------ |
| `sporadic` | `CONPD == 1` and all mutation-carrier flags equal zero |
| `genetic`  | mutation-carrier patients                              |
| `both`     | union of sporadic and genetic cohorts                  |

Missing values are encoded as `.` in the source file and are treated as zeros during cohort classification.

This file must remain at the top level of `data/`.

# What is generated elsewhere?

The code does not write derived outputs into `data/`.

Generated outputs are written to:

| Folder        | Contents                                                                                                                    |
| ------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `saved_data/` | Pickled intermediate datasets, patient subsets, low-dimensional spaces, model inputs, model outputs and performance results |
| `figures/`    | Generated plots and publication figures                                                                                     |

The `saved_data/` folder contains patient-level derived data and must be treated with the same access restrictions as the raw PPMI files.

# Before making this repository public

Do **not** make this repository public while `data/` or `saved_data/` are present in the Git history.

Deleting the files from the current folder is not enough. Once committed, these files remain recoverable from previous Git commits.

A normal command such as:

```bash
git rm -r data/
git commit
```

does **not** remove the data from Git history.

## Recommended option: create a clean public repository

The safest approach is to create a new repository that contains code only.

Steps:

1. Copy the code files into a new directory.
2. Do not copy the `.git/` folder.
3. Delete `data/` and `saved_data/`.
4. Add a `.gitignore`.
5. Run `git init`.
6. Push the new code-only repository.

Recommended `.gitignore` for a public repository:

```gitignore
# Access-controlled PPMI data — never commit
data/
saved_data/
*.pkl
*.xlsx
```

## Alternative option: rewrite repository history

If this repository must be converted into a public repository, use a history-rewriting tool such as:

* `git filter-repo`
* BFG Repo-Cleaner

to purge `data/` and `saved_data/` from every commit.

This rewrites commit history, so all collaborators will need to re-clone the repository. Existing forks or mirrors may still contain the original data.

## Final public-release checks

Before publishing, also check:

* `figures/`
* exported plots
* notebooks, if any
* temporary files
* cached files
* any files containing `PATNO` or patient-level trajectories

No raw or patient-level PPMI data should be present in the public repository.
